# birss-app ↔ Birss Tables: Convention Contract & Verification Ladder

> **Content:** The convention contract and verification ladder: how the app maps onto Birss/ITC, step by step, with a per-step anti-circular test.
> **Status:** living
> **Authority:** AUTHORITATIVE for the app's conventions. It outranks the vendored book compilation where the two are compared; where Birss and ITC diverge, Birss wins.

**Purpose.** Guarantee that, for every **Default group**, `manganite/birss-app` reproduces the Birss tables *in every respect* — name, axes, generators, operation set, and tensor components, and specify a safe, table-anchored test for each link in the chain.

**Central app references.** This document and its companion **[`table-nomenclature.md`](../../birss-tables/table-nomenclature.md)** (the 122-group Schoenflies / full-HM / Shubnikov / operator / generator table) are the two central convention references for the app. For Birss↔ITC divergences (symbol/orientation) and Birss's Table-7 bracket semantics, see the companion **[`BIRSS-ITC-CONVENTION-DIVERGENCES.md`](BIRSS-ITC-CONVENTION-DIVERGENCES.md)**. This document is **self-contained**: all conventions are explained here in full. It references the frozen Birss **data tables** (`table-3`, `table-4a`, `table-4e/4f`, `table-6`, `table-7`) and `table-nomenclature.md` for *data* (symbols, matrices, forms), and the Birss book for equation numbers, but no explanation is deferred to another narrative document.

**Authority.** R. R. Birss, *Symmetry and Magnetism* (1966); the frozen transcriptions in `birss-tables/` (this repo). Where Birss and ITC diverge, **Birss wins** (see Step 1).

**Scope.** Default (setting-1) groups only. Birss tabulates a single setting per group; alternative axis settings (the orthorhombic setting taxonomy) are a separate concern and are explicitly out of scope here.

**Anti-circularity (non-negotiable).** Every expected value at every step is read from a Birss table (`table-3`, `table-4a`, `table-4e/4f`, `table-6`, `table-7`), never generated by running the app. A test that compares the app to itself proves nothing.

---

## The dependency ladder

```
(1) names ──┐
            ├──▶ (3) generators ──▶ (4) operation set ──▶ (5) tensor components
(2) axes ───┘
```

Steps **4 and 5 are deterministic consequences** of 1–3: group closure (4) and tensor projection (5) are algorithms with no free choices. So the correctness effort lives in **1–3**; steps 4–5 are *checks that 1–3 were right*. Crucially, **(1) and (2) are coupled** — the canonical symbol is only defined once the axis setting is fixed (the same abstract group carries different HM symbols in different settings). Treat 1+2 as a single "identity+orientation" decision, then read generators (3) off the tables in that frame.

Each step below states: **the contract**, **the source table**, and **the test**.

## Step 1 — Group names

### Contract
The app's group **key set** must equal the Birss symbol set for all 122 groups, in a single fixed notation variant, in the Birss axis setting (Step 2).

- **90 groups** (32 classical Type I + 58 black-white Type III): names taken from Table 3 (classical) / Table 6 (black-white), **in the app notation variant** — identical to Birss except the cubic short-symbol convention below (app keeps `-3`/`-3'` where Birss Table 6 prints the bar-less `m3` form).
- **32 grey groups** (Type II) are **absent from Table 6** and are derived from the 32 classical by the fixed rule **grey = 𝒢 ⊗ {1, 1′}**, symbol = classical symbol **+ `1'`** (e.g. `mmm` → `mmm1'`, `222` → `2221'`). Their tensors follow trivially (Step 5: i-tensor = parent's, c-tensor ≡ 0).

### Birss-over-ITC invariant (the one orthorhombic divergence)
The group D₂ₕ(C₂ₕ) — unprimed inversion, one unprimed 2-fold + its mirror — is named:

| Source | Symbol | un-primed 2-fold |
|---|---|---|
| **Birss (app must use this)** | **`m'm'm`** | 2_z |
| ITC Table 1.5.2.3 | `mm'm'` | 2_x |

The app **must** carry `m'm'm` (2_z) and **must not** introduce `mm'm'`. This is the only orthorhombic point where the two references disagree; because the two symbols differ by a single prime position, it is the easiest orthorhombic group to mislabel — carrying `mm'm'` would pair the key with the wrong operator set.

### Notation-variant decision & data source
**Canonical key = abbreviated (short) Hermann–Mauguin**, in the app's notation, which *is* transcribed in the repo (table-3 / table-6), so Step-1 tests have a source of truth. App notation rules (fixed since v1, deviating from Birss where noted):
- **Time reversal = prime `'`** (not the Birss/ITC Shubnikov underline).
- **Inversion = leading `-`** (`-1`, `-4`, `-3`).
- **Cubic:** keep the inversion bar on the 3 (`-3`) and its prime where present (`-3'`), e.g. `m-3`, `m'-3'm'`, `m'-3'm` — standard HM usage, **unlike** Birss Table 6's bare `m3` / `m'3m'`. (This is an app-vs-Birss short-symbol difference, not a group difference.)

**Data source.** Full HM and pure-magnetic-group **Schoenflies** are not in `birss-tables`; both are provided for all 122 groups in **[`table-nomenclature.md`](../../birss-tables/table-nomenclature.md)**, transcribed from ITC Table 1.5.2.3 and joined to the app keys by abstract group `G(H)`. Notes:
- Grey (Type II) Schoenflies use the ITC **subscript R** (D<sub>4R</sub>); HM uses `…1'`.
- Full HM is given in the **app (Birss) setting** (monoclinic z∥c ⇒ `112`, not ITC b-unique `121`; D<sub>2h</sub>(C<sub>2h</sub>) ⇒ `2'/m' 2'/m' 2/m`); the ITC form is recorded per-row.

### Test
Assert `keys(GENERATORS) ∪ grey-derived` == `symbols(table-3) ∪ symbols(table-6) ∪ (+1' rule)`, as sets, in the chosen variant. Explicitly assert `m'm'm ∈ keys` and `mm'm' ∉ keys`.

## Step 2 — Coordinate axes / orientation

### Contract
Each Default group's reference axes follow **Birss Table 4a** ("Orientation of reference axes"), verbatim, in the app's orthonormal Cartesian frame. The app uses **pure point-group generators, no lattice/metric** — so "axes" means the Cartesian directions assigned to the symmetry elements, nothing more.

**Per-system axis convention (Birss).** The frame `x,y,z` (= `Ox₁,Ox₂,Ox₃`) is right-handed orthonormal, fixed in the crystal (not the possibly-oblique `a,b,c`):
- **Triclinic:** no constraint.
- **Monoclinic:** **z** is the unique axis — the 2-fold itself (class `2`) or the mirror normal (class `m`); Table 4a `2//z`, `-2//z`. This is Birss's **z-unique** setting; ITC's **b-unique** convention plays the same role with `b`, so ITC sources need a permutation.
- **Tetragonal / trigonal / hexagonal:** **z** = principal axis (4-, 3-, 6-fold = `c`). **y** = either a secondary 2-fold ⊥ z (classes with `2⊥`, e.g. `32`, `422`, `622`; generator σ(2)=[2_y], Table 4a `2//y`) or a mirror normal for a plane containing z (classes `3m`, `4mm`, `6mm`; σ(4)=[-2_y], `-2//y`). **x** completes the right-handed frame.
- **Orthorhombic:** `x,y,z` = the three mutually ⊥ 2-folds (or mirror normals); Table 4a `2//x, 2//y` (`2//z` implied).
- **Cubic:** `x,y,z` along the cube edges ([100], the 4- or 2-folds); the four 3-folds lie along body diagonals ([111]) and are **not** coordinate axes (σ(9) realizes one by cyclically permuting x→y→z).

### Load-bearing cases (where axis conventions silently diverge)
1. **Monoclinic:** Birss first setting **z ∥ c** (y ∥ b\*, x ∥ a). ITC second-setting (b-unique) sources need permutation. App follows **Birss (z ∥ c)**.
2. **Bracketed / rotated groups — component-critical for the app.** A parenthesized symbol denotes the **same abstract group** as the unparenthesized version, but in a **non-standard axis orientation** within the crystal frame (it inherits the frame of the magnetic group it was derived from, without re-orienting to the standard HM setting). Because tensor components are tied to the fixed crystal axes, such a group **suppresses different specific components** than the standard-orientation group — so for the app's component-level work the rotated orientation **must** be honoured. (For the coarser Table-4a *symbol-class* lookup the two are equivalent, which is why Birss's own tables treat them interchangeably there.) They are:

**Default bracketed magnetic groups** — these *are* Default (Table A) keys; the **Table-6 operator list is the authority** for their orientation (read the axes off the actual operators, not off a naive x-y-z reading of a re-derived symbol):

| Default key | abstract group | Birss orientation (non-standard) |
|---|---|---|
| `2'm'm` | C₂ᵥ + time reversal | 2-fold ∥ **a** (not c); operators `1, -2_z, 2'_x, -2'_y` (Table 6) = {m_z, 2′_x, m′_y} |
| `-4'm2'` | D₂d + time reversal | rotated setting of D₂d |
| `-6'2m'` | D₃h + time reversal | rotated setting of D₃h |

**Alternate-setting pairs** (context only — *not* Default keys, and alternate settings are out of scope here): the classical `-4m2`/`-42m` (D₂d) differ by a **π/4** rotation and `-62m`/`-6m2` (D₃h) by **π/6**. The app's Default key is `-42m` (D₂d) and `-6m2` (D₃h); the other member of each pair is an alternate setting, not tabulated as a Default.

### x-y-z positional rule (orthorhombic and generally)
Within an HM symbol, position 1 → x, position 2 → y, position 3 → z (Birss Ch. 2). For orthorhombic groups this rule *is* the orientation, and the Default operator set must equal the x-y-z reading of the symbol. The bracketed groups are the cases where the symbol's own axis setting is non-standard, so the rule is applied to the **Birss symbol in its Birss setting** (Table 6), not to a normalized symbol.

### Test
For each group, assert the intended element→axis assignment equals Table 4a. For the **three default bracketed groups** (`2'm'm`, `-4'm2'`, `-6'2m'`), assert the Default operator directions equal the Table-6 operator list (this subsumes the x-y-z check). The alternate-setting pairs (`-4m2`/`-42m`, `-62m`/`-6m2`) are **not** Default keys and are out of scope for this test.

## Step 3 — Generators

### Contract
Generators are read from **Table 3** (classical, `σ(N)`) and **Table 6** (black-white, `σ(N)` unitary + `σ'(N)` antiunitary). The app's generators must be drawn from Birss's σ(0)–σ(9) pool (or an equivalent generator of the same group) and **close to Birss's operator set**; antiunitary generators carry the time-reversal flag (`σ'`).

**The σ(0)–σ(9) pool** (Birss eq. 2.17): ten fixed 3×3 matrices referenced by number in Table 3 / Table 6.

Explicit matrices, verbatim from eq. (2.17). They act on column coordinate vectors, v′ = σ·v (so σ(9) sends (x,y,z) → (y,z,x)):

```
σ(0) = [[ 1, 0, 0], [ 0, 1, 0], [ 0, 0, 1]]              identity  1
σ(1) = [[-1, 0, 0], [ 0,-1, 0], [ 0, 0,-1]]              inversion  1̄
σ(2) = [[-1, 0, 0], [ 0, 1, 0], [ 0, 0,-1]]              2_y
σ(3) = [[-1, 0, 0], [ 0,-1, 0], [ 0, 0, 1]]              2_z
σ(4) = [[ 1, 0, 0], [ 0,-1, 0], [ 0, 0, 1]]              -2_y = m_y   (mirror ⊥ y)
σ(5) = [[ 1, 0, 0], [ 0, 1, 0], [ 0, 0,-1]]              -2_z = m_z   (mirror ⊥ z)
σ(6) = [[-1/2, √3/2, 0], [-√3/2, -1/2, 0], [0, 0, 1]]    3_z          (120° about z)
σ(7) = [[ 0, 1, 0], [-1, 0, 0], [ 0, 0, 1]]              4_z          (proper 4-fold)
σ(8) = [[ 0,-1, 0], [ 1, 0, 0], [ 0, 0,-1]]              -4_z = 4̄_z   (roto-inversion, improper)
σ(9) = [[ 0, 1, 0], [ 0, 0, 1], [ 1, 0, 0]]              3-fold about [111]
```

σ(7) (proper) and σ(8) (roto-inversion) are **distinct** matrices; swapping them, or marking σ(7) antiunitary, changes the group. The app's `getRotationZ(90)` = `[[0,-1,0],[1,0,0],[0,0,1]]` is `4_z` in the *opposite* sense — an equivalent generator that closes to the same group, so it will **not** match σ(7) by raw-matrix equality (verify by closure — see Test).

`σ'(N)` = the same matrix σ(N) with the time-reversal (antiunitary) flag set. Table 3's "Generating matrices" column and Table 6's σ(N)/σ'(N) columns give the per-group generator sets.

- **Prefer** implementing generators as the Birss σ matrices verbatim; equivalent generators (e.g. a rotation of opposite sense) are acceptable — the correctness criterion is always **closure to the Table-6 operator column**, never the generator matrix itself.
- Prefer building alternate settings (out of scope here) via similarity transforms `G' = S·G·S⁻¹` with the antiunitary flag preserved — never by hand-writing rotated generators.

### Test
For each group, assert the app's **closed operator set** (matrices *and* antiunitary flags) equals the Birss **Table-6 operator column** for that row — the authority, independent of generator choice and rotation sense. Do **not** assert raw generator-matrix equality against the `σ(N)` column: the app may use an equivalent generator of opposite handedness (e.g. `getRotationZ(90)` = `4_z` CCW vs Birss `σ(7)` = `4_z` CW) that closes to the same group. As a cross-check, also close the row's `σ(N)`/`σ'(N)` generators: if that closure disagrees with the operator column, one of the two was transcribed incorrectly — resolve against the printed book page before trusting either.

## Step 4 — Symmetry operation set

### Contract
Closing the Step-3 generators yields exactly the "Symmetry operators" column of Table 3 / Table 6, as a set, with correct unitary/antiunitary character on each element.

This step has **no free choices**: if Steps 1–3 are right, closure is forced. It is the strongest single integration test.

### Test
For all 122 groups: assert `close(app_generators)` == `operators(table-3 | table-6)` as sets (matrix identity + antiunitary flag). For grey groups, assert the operator set == parent classical set `∪ {g·1' : g ∈ parent}`.

## Step 5 — Tensor components

### Contract
Given the correct operator set, the projected tensor form must equal the Birss tabulated form — **after** applying the app's intrinsic index symmetry (particularization).

**(a) Tensor-type → Table-7 column → form-table map:**

| App tensor | physical tensor | Table 7 column | form table | transform law |
|---|---|---|---|---|
| **ED** | electric-dipole SHG | Polar **odd** rank n (n=3) | Table 4e | polar: `T'=RRR·T` |
| **MD** | magnetic-dipole SHG | Axial **odd** rank n (n=3) | Table 4e (axial) | axial: `T'=det(R)·RRR·T` |
| **EQ** | electric-quadrupole SHG (output `Q_ij`, input `E_k E_l`) | Polar **even** rank m (m=4) | Table 4f | polar: `T'=RRRR·T` (rank-4 polar, no det factor) |

The **i / c** flag sets the antiunitary sign: an antiunitary operation contributes **+1** for i-tensors (time-even) and **−1** for c-tensors (time-odd).

**(b) Symbol class** for each (group, tensor, i/c) is read from **Table 7** (magnetic) or **Table 4a** (classical). **(c) Form** of that class is read from **Table 4e/4f**.

**(d) PARTICULARIZATION (the essential subtlety).** Tables 4a–4f give the **crystal-symmetry-only** general form — the most general tensor consistent with the point group *alone*, before any physical (intrinsic) index symmetry. On top of it the app imposes each channel's **intrinsic index symmetry**: always the two identical driving ω-fields in the **last two** indices (`E_j E_k` for ED/MD; `E_k E_l` for EQ, with `E_{kl}=E_{lk}`), and for EQ additionally the **leading pair**, because the induced quadrupole is itself a symmetric rank-2 object. Particularization applies this on top of the table form, adding equalities among the surviving components and reducing the independent count below what the table lists.

- **ED, MD** (rank 3, `χ_{ijk}`): symmetric in `(j,k)` → jk-symmetric.
- **EQ** (rank 4, `χ_{ij,kl}`; output pair `(i,j)` = the induced quadrupole `Q_{ij}`, input pair `(k,l)` = the two fields): symmetric in `(k,l)` **and** in `(i,j)`, the two pairs independent of each other — the **`ij_kl`** class (no pair exchange, no trace condition). *Amended 2026-07-29 (Q1).*

**Why the leading pair is symmetric (Q1, maintainer decision 2026-07-29).** The app's EQ convention is `Q_{ij} = χ_{ijkl} E_k E_l`, and the physical quadrupole moment is symmetric in its own indices, so `χ_{ijkl} = χ_{jikl}` — a frequency-independent symmetry of the source object, not of the fields. Sources, both verified against the project PDFs in `docs/references/`:

- **Hoshi et al., Phys. Rev. B 52, 12355 (1995)**, §II.A.3 — writes exactly the app's convention `Q_i j = Λ_{ijkl} E_k E_l` and concludes: *"Since Q_ij is a symmetric and traceless tensor, the following relations exist"* → `Λ_{ijkl} = Λ_{jikl}` (and `Λ_{11kl}+Λ_{22kl}+Λ_{33kl} = 0`). This is the load-bearing citation: same rank, same index order, same physical channel.
- **Pershan, Phys. Rev. 130, 919 (1963)**, §IV — in his `E·∇E` convention the χ *"symmetric in the last two indices"* is the quadrupole, while *"the part of χ antisymmetric in the last two indices can be written as"* the magnetization term. His symmetric pair is the (field, gradient) pair, which in the app's index order is the **leading** `(i,j)` pair; the antisymmetric complement is precisely the magnetic-dipole channel. Read index-by-index, the same statement: the `(i,j)` symmetry **is** the EQ/MD separation.

Consequently an antisymmetric-`(ij)` component in the EQ channel is not a quadrupole at all but MD-type admixture, which the app's separate MD channel already represents. Before Q1 the app symmetrized only `(k,l)`, so its EQ output carried those spurious components (e.g. 54 instead of 36 independent components for triclinic groups).

**Tracelessness is deliberately NOT enforced.** `Q_{ii} = 0` appears in the general multipole literature and in Hoshi above, but Hoshi is alone in imposing it in the SHG context, and modern EQ-SHG-RA practice works with the 36-component baseline. The app therefore stops at `ij_kl`. Any literature form transcribed from a traceless convention (Hoshi's `D_∞h` list among them) must have that accounted for explicitly in the fixture derivation.

So the app's form = the table form **with each channel's intrinsic symmetry imposed**, never the raw table count.

- *Worked check (ED):* `mm2` ED = class **E** → table-4e **E3 = 7** crystal-only components (zzz + xxz-family(3) + yyz-family(3)); symmetrizing `(j,k)` → **5** independent (`χ_xxz=χ_xzx`, `χ_yyz=χ_yzy`, `χ_zxx`, `χ_zyy`, `χ_zzz`). Table lists 7, app computes 5 — both correct in their own convention.
- *Worked check (EQ):* the `(k,l)` symmetrization identifies `χ_{ijkl}` with `χ_{ijlk}` and the `(i,j)` symmetrization identifies it with `χ_{jikl}` (e.g. `χ_xyxy = χ_xyyx = χ_yxxy = χ_yxyx` is one component); a class whose 4f row separates such permutations therefore yields *fewer* independent app components than the raw 4f entry. Baseline: group `1` has `6 × 6 = 36`, against the raw 81 and the pre-Q1 `9 × 6 = 54`.

Any Step-5 test must compare against this **particularized** form (ED/MD: symmetrize the 2 field indices of the table-4e row; EQ: symmetrize the last 2 *and* the first 2 indices of the table-4f row).

**(e) Grey groups:** i-tensor = parent classical i-tensor; **c-tensor ≡ 0** identically (Table 6 note). Cheap, strong check.

**(f) CANONICAL PRESENTATION (minimal basis, constraint view).** *Added 2026-07-30 (Q0).* Steps (a)–(d) fix the invariant *subspace*; this fixes how the app *presents and parametrizes* it. Two rules, both mandatory:

1. **Bases are minimal.** The projector's own dedup only removes directions that are *proportional* to an existing one, which is not enough: for a fourth-rank tensor on a 3-/6-fold group the in-plane families satisfy a multi-vector dependency (`chain2 + chain4 + chain5 = 3·chain1`), so the spanning set can exceed the true independent-component count. The app therefore reduces every basis to **RREF** wherever it is not already minimal, so `basisResults.length` *is* the independent-component count, and the RREF **pivots name the free parameters** (RREF being unique for a given span, that naming is well-defined). Reduction is skipped when the set is already minimal, so those cells stay bit-identical; a permanent audit asserts `basisResults.length === spanRank(basisResults)` for every cell.
2. **Component relations are a consistent constraint set, and per-component expressions are sums over parameters.** A relation list of one chain per basis vector is only honest when each vector's support is a proportionality class. Where several parameters meet in the same components it is not, and chains then overlap and contradict each other. The display is therefore: (i) one chain per **proportionality class** (components whose columns across the reduced basis are proportional); (ii) the residual **composite relations** among class representatives, each on its own line, in **Birss's printed style** — Table 4f writes them as a sum cell, e.g. row **L4**'s `xxxx` cell `yyxx+xyyx+yxyx` giving `χ_xxxx = χ_yyxx + χ_xyyx + χ_yxyx`, alongside its separate `yyyy` cell `xxxx` giving `χ_yyyy = χ_xxxx`. Sums and equalities are never mixed into one chain. Correspondingly, an induced-response component is expressed as a **sum over the parameters it depends on** (`Q_xx = (χ_xxxx + ½χ_xxyy)E_x² + …`), never as a single parameter times a fixed ratio — that shortcut asserts a proportionality the subspace does not have, and the tensor it implies need not even be group-invariant.

Worked reference: `3m`, rank 4, polar, i-type, `none` → 14 independent components, displayed as three pair equalities, `χ_xxxx = χ_yyyy`, eleven z-block chains, and the one composite above.

**Composite partner choice (recorded deviation, accepted 2026-07-30).** Inside a composite relation each partner is rendered as the **canonical (lowest-index) member of its proportionality class**, so the app prints `χ_xxxx = χ_xxyy + χ_xyxy + χ_xyyx` where Birss's row L4 cell reads `yyxx+xyyx+yxyx`. The Q0 work order's acceptance criterion asked for Birss's partner choice verbatim; this is a deliberate, reviewed deviation. It is semantically identical — every substitution (`yyxx→xxyy`, `yxyx→xyxy`) is one of the pair equalities printed on the lines directly above — and it is what a *general* formatter can produce: Birss's partner choice is a per-row typesetting decision of the printed table, so reproducing it verbatim would mean encoding table-row knowledge in the formatter and would not generalize to the other sum-cell rows (K4, N4, P4) or to the magnetic derivatives that read those rows through Table 7. Against the printed table, verify a composite by substituting through the adjacent class lines.

Evidence and verification record: `docs/findings/FINDING-2026-07-29-rank4-trigonal-hexagonal-overcount.md`.

### Class forms actually used (rank-3, jk-particularized)
- **D₃** (3 indep.): `χ_xyz=χ_xzy`, `χ_yxz=χ_yzx`, `χ_zxy=χ_zyx`
- **E₃** (5 indep., z-unique): `χ_xxz=χ_xzx`, `χ_yyz=χ_yzy`, `χ_zxx`, `χ_zyy`, `χ_zzz` (a-/b-unique = axis-permuted)

### Test
For each (group, tensor, i/c): (1) look up the class in Table 7 / 4a; (2) look up the class form in Table 4e/4f; (3) apply the app's intrinsic symmetry (jk for ED/MD; pair for EQ); (4) assert the app's computed form equals that particularized form. Never derive the expected form from the app. Confirm grey c-tensors vanish.

## Scope & recorded decisions
- **Canonical group key** = the short Hermann–Mauguin symbol in the app's notation (Step 1). The full HM and magnetic Schoenflies notation for all 122 groups are in [`table-nomenclature.md`](../../birss-tables/table-nomenclature.md).
- **Alternative axis settings are out of scope here** — this document covers the Default (setting-1) group only. For reference, the orthorhombic setting scheme is: Default = c-unique, `ORTHO_CYCLIC` = a-unique, `ORTHO_REVERSE` = b-unique; 7 groups have three meaningful settings, 5 have none (maximum 3, never 4). Settings are realized via similarity transforms (Step 3), never hand-written generators.
